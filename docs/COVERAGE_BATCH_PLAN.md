## 1. The ONE voice start/stop path (design that every item plugs into)

All of items 4, 10, 11, 12, 13, 14, 19 and the existing module note limit touch note-on/off. Proposed shape, replacing the body of `ds_native_engine_note_on`/`note_off`/`trigger_zones`/`start_voice` in `native_engine.c`:

```
note_on(note, vel):
  if vel == 0 → note_off
  [11] fire <note> listeners matching (note, note_on|any, enabled); if any matching listener has swallowNotes → mark swallowed[note]=1 and RETURN
  ctx = { note, vel, prev_note = e->last_note (−1 if none), keys_before = e->keys_held, interval = note − prev_note }
  global-envelope start (unchanged), note_velocity[note]=vel, note_on_frame[note]=e->frame_clock   [14 needs the time]
  enforce_note_limit (module poly, unchanged; now calls silence_voice(FAST))
  note_counter++
  trigger_zones(ctx, ATTACK)   → per selected zone: start_voice(ctx, zone)
  e->last_note = note; e->keys_held++ (moved here from the top so ctx.keys_before is “before this note”)

start_voice(ctx, z):
  [10] choke pass: for every active voice w with (w->note_id != e->note_counter) and (w->zone->silenced_by & z->tag_mask): silence_voice(w, w's silencingMode/Decay)
  [4]  tag polyphony: for each tag t in z->tag_mask with e->tag_polyphony[t] > 0: while count(active, !choked, tag t) >= limit → silence_voice(oldest such voice, ITS silencing settings)
  allocate_voice (unchanged stealing)
  bounds = live_bounds(z)        [16: SAMPLE_START/END, LOOP_START/END overrides; 5: crossfade]  stored IN the voice
  [13] glide: if glide_time>0 and (mode==always or (mode==legato and ctx.keys_before>0)) and ctx.prev_note>=0: v->glide_semis = ctx.prev_note − note, v->glide_step = −glide_semis / (glide_time·rate) per frame
  [14] one-shot release voice: v->rt_gain = decay(held = (frame_clock − note_on_frame[note]) / rate)
  [19] v->delay_left = delay frames (seconds·rate | samples | beats·60/bpm·rate)
  envelope / modulators / stream word as today (stream word LAST, release-store; worker reads bounds from the voice after acquire)

note_off(note):
  [11] fire <note> listeners (note_off|any); if swallowed[note] → clear, RETURN (no release triggers)
  release key_down voices (sustain pedal unchanged) — a voice silenced with mode "normal" is already in RELEASE
  release triggers: trigger_zones(ctx, RELEASE) (round robin unchanged)
  keys_held−−; global envelope release; note_velocity[note]=0
  (last_note is NOT cleared: previousNote means "previously triggered note")

silence_voice(v, mode, decay):   ONE primitive replacing choke_note's body
  decay > 0        → env_release_coef = coef_for(decay), stage RELEASE, choked=1
  mode == normal   → release_voice(e, v) (the zone's own release), key_down=0 (counts as a released note for the module limit)
  mode == fast     → coef_for(0.005), RELEASE, choked=1   (the existing 5 ms choke; see OQ-1)
```

Realtime safety: everything above is O(voices × tags) integer work on fixed arrays; no allocation. The worker only gains: read `v->bounds` (plain fields written before the stream-word release-store, read after the acquire-load; the CAS on publish already discards a fill for a restarted voice).

`trigger_zones` gains the ctx and `zone_matches` gains: [12] trigger kind (attack | first ⇔ keys_before==0 | legato ⇔ keys_before>0 | continuous → treated as attack, OQ-3), previousNotes list (prev_note ∈ list), legatoInterval (prev_note == note − interval); [16] group-level LO/HI_NOTE, LO/HI_VEL overrides (`groups_rt[g].has_lo_note ? … : z->def.lo_note`).

`render_voice`: `inc = rate_ratio · 2^(( (note − root_live) · key_track + tuning + glide_semis ) / 12)` where root_live = group ROOT_NOTE override or `def.root_note` [3,13,16]; `glide_semis` steps toward 0 per frame; frames while `delay_left > 0` output nothing and advance nothing [19]; `fetch`/`map_frame` take the voice's bounds and apply the loop crossfade [5]; `gain *= v->rt_gain` [14].

### Item 5 — loop crossfades — S–M
Doc: `loopCrossfade`: "instead of simply looping at a specific end point, a portion of the audio from before the loop point is faded in just as the audio from the end of the loop is faded out … This parameter is used for specifying the length of the crossade region in frames/samples. This can also be set at the <group> level. Default: 0 (crossfades off)." `loopCrossfadeMode`: "the curve used for crossfading … Value values: linear, equal_power. Default: equal_power."
Reading (OQ-4): in the last `xf` frames of each loop pass (file frame f ∈ [loop_end − xf, loop_end)), out = A(f)·g_out(t) + B(f − loop_len)·g_in(t), t = (f − (loop_end − xf)) / xf, loop_len = loop_end − loop_start; B is the audio BEFORE loopStart. xf is clamped to min(xf, loop_start − zone.start, loop_len) — so CS-20M/DS Synths (`loopStart="0"`, xf 9–10) get xf = 0 → identical output to today (guards regression); RJS Guitar (loopStart 200000, xf 4900) gets the real fade. linear: g_out = 1 − t, g_in = t; equal_power: g_out = cos(tπ/2), g_in = sin(tπ/2).
Design: parser reads both (inheritable; mode default equal_power). `ds_zone_t`/voice bounds gain `xf, xf_equal_power`. Audio thread: `fetch()` — when `f < head_frames` and in the fade region, mix from the head (f − loop_len < f so it is in the head too). Worker: `fill()` writes PRE-MIXED frames into the ring for the fade region (two reads: the region itself and `f − loop_len`, which may be head-resident or on disk) — so the audio thread never needs a second ring. `resolve_bounds` marks `streams` unchanged. Cost: per-frame branch on `f >= fade_start` plus a cos/sin per frame only inside the region — precompute per block or use a small table? Simplest exact: compute `g_in/g_out` per frame with `sinf/cosf` only inside the region (≤ xf frames per loop pass); fine for xf ≤ a few thousand. Cap xf at e.g. 65536.
Test (`tests/test_loop_xfade.c`, REAL plugin at real-time pace, like `test_render` B): file 60000 frames (loop beyond the head so the ring path is exercised), `loopStart=30000 loopEnd=49999 loopCrossfade=2000`; expected value per output frame computed from `test_signal24` with the formula above, both modes, 1e-5. Also assert `loopStart=0` + xf 9 renders bit-identical to xf 0. Mutations: fade region placed at the loop start instead of end; equal_power/linear swapped (mid-fade sample differs by ~0.2); worker not pre-mixing (mismatch once past the head).

## 5. Risks
- **CPU** (Cortex-A72, budget ≪ 900 µs/128 frames): choke/tag-poly passes are O(64 voices) per note-on (integer) — negligible. Loop crossfade: ≤ 1 branch/frame plus `sinf/cosf` only inside the fade window; cap xf at 65536 frames. Glide: one `pow` per block per gliding voice + one multiply/frame (no per-frame pow). Gate/bitcrusher: a few ops/frame. Compressor: one `log10f`/`powf` per FRAME is too much → compute gain per 8 or 16 frames or use `fast log2` approximation; test tolerance ±0.1 dB allows it. FLAC decode is worker-only; a 64-voice FLAC library at 48 k stereo ≈ 6 MB/s decode — fine for the worker, but `ds_native_engine_service` fills up to 4096 frames per voice per pass; check the perf log line (`perf:` in `engine_worker`) on device. Retrigger check is O(128) ints per block.
